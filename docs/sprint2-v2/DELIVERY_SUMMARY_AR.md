# تسليم SolveIt — Sprint 2 / Case Core v2
تاريخ التسليم: 2026-10-01. العقد: 2.0.0.

تم تنفيذ التوسعة المعتمدة على نسخة المشروع الكاملة، مع الحفاظ على فصل User وExpert وAdmin.
هذه حزمة باك إند متحققة محليًا؛ لا تعني نجاح Staging أو اكتمال التكامل مع React.

## ما تم تنفيذه
- Service Catalog من قاعدة البيانات: الدول والنطاقات القانونية والمجالات والتخصصات والخدمات ووسيلة تقديمها.
- سياسات خدمة بإصدارات ثابتة، مراجعة، Impact Preview، نشر وإيقاف وسجل تدقيق، وست صلاحيات مستقلة.
- مراجعة أدمن صريحة تربط اعتماد الخبير الحالي بالتخصص والخدمة والـJurisdiction بناءً على الأدلة.
- Case Core v2: Draft، حفظ واستئناف، اختيار عدة نطاقات، Intake ديناميكي، تقييم وتأكيد وإرسال وإلغاء.
- فصل دولة المستخدم عن دولة القضية وعن نطاق الخدمة. دعم GLOBAL وCOUNTRY_SPECIFIC وMULTI_COUNTRY.
- عدم إعلان الجاهزية دون خدمة مفعلة، بيانات وموافقات ومستندات مكتملة، وتغطية خبراء مؤهلين لكل نطاق.
- تقديم جزئي بموافقة واضحة، مع إبقاء القضية الكاملة غير جاهزة ما دام جزء منها غير جاهز.
- تثبيت نسخة السياسة ومراجع بيانات Intake وContext والمستندات والموافقات عند الإرسال.
- منع Expert من الوصول للقضايا، وقصر الأدمن على metadata حسب صلاحيات مستقلة.
- إصلاح توقيت ContractFixturesTest، وحماية استجابة إعادة الطلب من تغير شكل JSON.

## البنية والتوافق
Controllers خفيفة، Form Requests، Resources، Gates/Policies، خدمات للعمليات متعددة الخطوات،
Transactions وexpectedVersion وIdempotency-Key وlockForUpdate للتحولات ذات الصلة.
أضيفت ستة جداول للكتالوج والإصدارات والمنح ونطاقات القضية وقفل المزامنة، مع أعمدة جاهزية في cases.
أعيد استخدام Profile/Contexts/KYC/Renewal/Audit والمستندات الخاصة؛ لم تُعد هندسة المصادقة.
يظل v1 قابلًا للقراءة وحفظ المسودات، لكن إرسال القضية يجب أن يمر من عقد v2 ولا يتجاوز الكتالوج.
القضايا لصاحب الحساب فقط. لا توجد قضايا نيابة عن الآخرين.

## نتائج التحقق
- 282 اختبارًا ناجحًا من282، و2548 assertion.
- Composer strict وPint ناجحان.
- Larastan: المستوى5 للوحدات الجديدة، والمستوى0 للمشروع القائم؛ لا ادعاء بتغطية المشروع كله بالمستوى5.
- فحص70 ملف PHP دون خطأ نحوي.
- 14 فحص ترقية/seeders/routes/scheduler/rollback/re-upgrade ناجحة على SQLite مع بقاء المستخدم التجريبي.
- اختبار queue ومستند مشفر وإرسال v2 عبر عمليات PHP منفصلة ناجح، باستخدام scanner تجريبي.
- 35 مسارًا جديدًا؛32 fixture لعقد v2 و13 للمستندات والسياق والـtimeline المشتركة.

## ما يحتاج بيئة التشغيل
تفعيل السياسات الحقيقية وخبراء مؤهلين، Base URL وحسابات اختبار، محرك قاعدة بيانات Staging لاختبار
التزامن، scanner حقيقي، التخزين الخاص المشترك، queue/scheduler وCORS، ثم قبول React.
الـ41 خدمة الأولية templates بحالة draft؛ لا يتم إطلاقها تلقائيًا.
بوابة Sprint1 Staging، الـSLA الفعلي، وإصدارات السياسات الفعلية ما زالت تتطلب بيانات واعتماد البيئة.

## خارج هذا التنفيذ أو يحتاج قرارًا منفصلًا
Matching/تعيين فريق أو منسق/Booking/Payments، الحذف النهائي وإخفاء الهوية، وتنفيذ واجهات React.
تصدير بيانات Case ضمن Data Export v1 وسياسة الاحتفاظ/حذف المسودات لم يُوسعا ضمن هذا العقد.
حالة requires_review لا تُرفع تلقائيًا؛ لا توجد صلاحية لتجاوز شروط الأهلية أو ترخيص الخدمة.
التصنيف قواعد deterministic قابلة للاختبار، وليس تشخيصًا مهنيًا أو ضمانًا لاكتشاف كل نص خطر.

راجع DEPLOYMENT.md للأوامر والـrollback، ENDPOINTS.md وPERMISSION_MATRIX.md وDATABASE_MAPPING.md
للتفاصيل، وFRONTEND_HANDOFF.md وAPI_SCHEMAS.json والـfixtures لفريق React.
