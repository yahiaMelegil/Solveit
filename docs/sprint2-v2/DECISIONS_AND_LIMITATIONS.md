# Approved decisions and limits
## Applied decisions
Self cases only; Career is non-legal guidance. Separate account realms retained. Case Core v2 allows expanded
states; v1 reads/drafts remain and submit cannot bypass current catalog. Service type differs from delivery mode.
Explicit admin evidence grants link existing Verified Scope to exact catalog version/service/jurisdiction.
ContractFixturesTest clock is now fixed before seed creation. No test exclusion hides that defect.
No mandatory AI provider: deterministic database rules propose only real catalog values; user confirms.
Countries, domains, specialties, services, jurisdiction policy and operational activation are database data.
Static Enums are finite lifecycle/mode values only. Existing KYC classification now reads DB domain policy;
`catalogPolicyVersionId` is an additive optional KYC scope input for stricter mixed-domain professional licensing.
Renewal preserves professional requirements and does not carry catalog grants onto new scope automatically.

## Limits that matter
- Eligibility is current evidence and supply, not a booked expert, ranking, team assignment or workload reservation.
  Multiple scopes/min/max expert requirements support future teams; coordinator assignment is future Matching.
- Safety keyword rules are deterministic indicators, not exhaustive detection, professional diagnosis or AI scoring.
  Ambiguous/restricted intake stops; a staffed human support channel must be provided operationally.
- Initial 41 service templates are not approved live services. No real expert/license data was fabricated.
- requires_review is a holding state, without an automatic override/clear API. Operator review or a new self-owned
  intake is needed; future matching must revalidate eligibility rather than trusting an old ready timestamp.
- New safety-rule publication invalidates pending confirmations. Already submitted cases are reviewed for blocked
  service/professional coverage by the command; a newly discovered content risk requires explicit service block
  and operator assessment. There is no automatic reinterpretation of historical narratives under arbitrary rules.
- Shared taxonomy status cannot be disabled after first publication; pause/block versioned entries for impact-safe
  changes. Taxonomy labels can change, stable codes/classification/parents cannot. No delete-used-entry API.
- Every selected MULTI_COUNTRY policy requires its full jurisdiction set; select separate entries for independent
  partial-country work. Partial submission requires explicit consent and never reports the whole case ready.
- Account export v1 still explicitly excludes Case data (`case_data_outside_export_v1`). A versioned Case-inclusive
  export/retention policy is a separate unresolved privacy product decision; no silent deletion/retention SLA added.
- Hard deletion/anonymization remain excluded by user. No automated draft purge or financial/legal deletion added.
- API labels are Arabic/English; reason codes require React localization. No React interface is built in this backend patch.
- Staging, real database lock contention, real antivirus, shared private storage, live CORS and React E2E are unverified.
- Strict static analysis is level5 for new catalog/v2 modules. Whole existing app passes level0; its higher-level
  historical Eloquent typing debt is not claimed fixed. Larastan is development-only, not a runtime dependency.

A local backend delivery can be reviewed independently; it is not Sprint1 release-gate closure or production approval.
